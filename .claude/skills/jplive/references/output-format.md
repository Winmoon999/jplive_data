# 報告格式

報告是 Markdown 檔，存放在 `reports/jplive-YYYY-MM-DD.md`，由 `python scripts/report.py` 依資料庫產生。**格式固定，不要手寫覆蓋**，這樣每天的報告才能互相比較。

## 報告內容（由腳本產生）

1. **本次新增**：`first_seen_at` 在起算時間之後的活動。
2. **本次變更**：`last_changed_at` 在起算時間之後、且不是新增的活動。
3. **近期票務**：未來 `ticket_window_days`（預設 14）天內，票務開始、截止、結果公布的時間點。
4. **關注清單：即將到來的 Live**：依藝人分組；沒有已知未來 Live 的藝人明確標示。
5. 頁尾：產生時間與資料庫更新時間。

每個活動顯示：標題、可信度（官方確認／僅整合站／傳聞）、陣容是否未完整公布、各場次（日期含星期、場館與都道府縣、開場／開演）、票務階段（時間 JST、價格、購買限制）、備註、來源連結。

## 對話中的簡短回覆

報告檔之外，對話回覆保持簡短：

```
已更新 {N} 位藝人：新增 {a} 筆、變更 {b} 筆。
重點：{最近要開賣或截止的票務 1–3 項}
沒有新資訊：{藝人名}
抓取失敗：{來源}（會於 24 小時後重試）
報告：reports/jplive-YYYY-MM-DD.md
```

## 單次查詢查無結果

```
目前未查到「{對象}」{時間範圍}公開的日本 Live 資訊。
已查來源：……
已用關鍵字：……
可能尚未公布；可稍後再查，或把它加入關注清單進行每日追蹤。
```

## 文件格式

預設是 Markdown。如果使用者需要 Word 或 PDF，可由同一份 Markdown 轉換；格式需求要等使用者明確指定，不要自行猜測。
